# Deterministic generation: one schema, three backends, byte-equality as the proof

## Context

B1 generates per-point AI study content (explanations, memory aids, drills) through a Python CLI. There is
no API key in CI, and the repository's gates must run offline. The design therefore has three interchangeable
backends behind one schema: `cli` (OpenAI-compatible HTTP, the production path), `agent` (a harness agent
fills the same JSON by hand when no key exists), and `replay` (recorded fixtures, used by CI and tests).

The risk is drift: three code paths that "should" produce the same document will diverge unless something
forces them together, and a green suite proves nothing if the fixture path silently reads stale or absent
data.

## Guidance

- **All backends must pass through one validation function.** `complete_json()` → `validate_schema()` is the
  single gate; the three backends differ only in how the payload is obtained. Assert field-identity
  across backends rather than "each backend validates".
- **Byte-equality is the acceptance test, at whole-artefact granularity.** Compare the complete emitted file
  (the content artefact), not a subset of fields, and do it for: replay re-run, incremental merge vs full
  generation, and the committed artefact vs a fresh build. Normalise exactly one declared field
  (`generated_at`) and nothing else.
- **Confine nondeterminism to declared fields.** Every emitted-byte non-determinism must be traceable to a
  documented `generated_at` (or equivalent). A generation or render path must not read the clock beyond that
  one date, `HEAD`, the network, environment-specific ordering, or uncommitted local state.
- **The keyless backend must fail closed, never template.** When the hand-back result is missing, the `agent`
  backend exits non-zero with the missing-stage message and produces **no** artefact. A placeholder or
  template fallback would silently ship ungrounded content.
- **Fixtures must cover the whole input set, and the replay path must not need scratch state.** Prove the
  offline path is self-contained by moving the handed-back task scratch directory aside and re-running: a fixture-backed replay
  must still reproduce byte-identically.
- **Batch generation needs a canonical order.** When content is produced in slices and merged, define one
  canonical ordering (here: chapter ordinal → section index → `point_id` → block kind) and assert that the
  incremental merge and a single full pass are byte-equal. Without it, merge order leaks into the artefact
  and the byte-equality test becomes unreproducible.
- **Test fixture roots must be injectable.** Rooting fixture/prompt paths at `__file__` at import time makes
  a test that uses a copied repository silently read the real one — which is how B1's "failed build writes
  nothing" test passed for the wrong reason. Provide a `set_repo_root()`-style seam and assert inside the
  test that the resolved fixture root is inside the copied tree.

## Why This Matters

The public repository promises traceable, reproducible content. If a generated artefact cannot be rebuilt
byte-for-byte from committed inputs, no reviewer can verify what changed between two runs, and the "AI
content is labelled and grounded" claim loses its audit trail. Offline reproducibility is also what lets CI
enforce the labelling and plagiarism rules without network access or an API budget.

## When to Apply

- Recording or refreshing fixtures for a new course batch (B2/B3).
- Adding a backend, a prompt version, or a new block kind.
- Reviewing a claim of the form "the two paths produce the same output": require the artefact-level byte
  comparison and the exact normalisation list.

## Examples

### Before

A batch generator merges per-chapter JSON in whatever order the batches were produced; the test compares
selected fields, and the fixture path resolves via `__file__` to the developer's checkout.

### After

Every backend returns through the same completion call, which validates against the shared schema before the
payload is accepted. The incremental merge and a single full pass are asserted byte-equal under one canonical
ordering, and a second replay run is asserted byte-equal to the first with only the declared timestamp
normalised.
